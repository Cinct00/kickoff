# Token Efficiency and Context Engineering Techniques for Cross-LLM Agent/Skill Toolkits (2025–2026)

Research date: 2026-11-03. Primary sources are Anthropic engineering posts (Jun 2025 – Nov 2025) and current Claude API / Claude Code docs (fetched 2026-11-03, which reference Claude Code versions up to ~v2.1.310 and models up to Opus 5.5 / Sonnet 5.5 / Fable 5.1). Note: developers.openai.com, cursor.com and geminicli.com were unreachable from this research session (network allowlist), so Codex / Cursor / Gemini findings come from search-result snippets of those official pages plus third-party write-ups, and are flagged accordingly.

## 1. Progressive disclosure in Agent Skills (front-matter preload, on-demand bodies, size limits, splitting)

### Takeaway
Skills are a three-tier progressive-disclosure system: only `name` + `description` sit in context at all times; the `SKILL.md` body loads on invocation (and then stays as a recurring cost); reference files and scripts cost zero tokens until read/executed. Anthropic's concrete limits are: name ≤64 chars, description ≤1,024 chars (API spec) / listing entry truncated at 1,536 chars (Claude Code), body <500 lines, references one level deep, TOC for reference files >100 lines, and the whole skill listing is budgeted at ~1% of the context window in Claude Code.

### Cited Findings
- At startup only the metadata (name and description) of all Skills is pre-loaded into the system prompt; Claude reads `SKILL.md` only when the Skill becomes relevant, and reads additional files only as needed. "Reference files, data, or documentation don't consume context tokens until actually read." — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Front-matter constraints: `name` max 64 chars, lowercase letters/numbers/hyphens only, no XML tags, no reserved words `anthropic`/`claude`; `description` non-empty, max 1,024 chars, no XML tags, should state what the skill does AND when to use it, written in third person (it is injected into the system prompt). — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- "Keep the `SKILL.md` body under 500 lines for optimal performance"; split into separate files when approaching the limit. — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); same 500-line tip in [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Keep references one level deep from `SKILL.md`; with nested references Claude may only `head -100` preview files and get incomplete information. Reference files >100 lines should start with a table of contents. — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Organize references by domain (e.g., `reference/finance.md`, `reference/sales.md`) so only the relevant one is read; include grep hints in SKILL.md. Concise vs verbose example: ~50 tokens vs ~150 tokens for the same instruction ("Default assumption: Claude is already very smart"). — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Bundled utility scripts "save tokens (no need to include code in context)"; scripts run via bash and "only the script's output consumes tokens." Make execute-vs-read intent explicit ("Run `analyze_form.py`" vs "See `analyze_form.py`"). — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Claude Code: combined `description` + `when_to_use` text is truncated at 1,536 characters in the skill listing "to reduce context usage" — put the key use case first (configurable via `skillListingMaxDescChars`). — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Claude Code: the listing's character budget "scales at 1% of the model's context window"; when it overflows, descriptions are dropped starting with least-invoked skills (names always kept). Raise via `skillListingBudgetFraction` (e.g., 0.02) or `SLASH_COMMAND_TOOL_CHAR_BUDGET`; `/doctor` estimates listing cost; `/context` Skills row reports post-budget size. — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Visibility controls: `disable-model-invocation: true` removes the description from context entirely (body loads only when user invokes); `user-invocable: false` hides from `/` menu but description stays in context; settings `skillOverrides` per skill = `"on" | "name-only" | "user-invocable-only" | "off"`; `disableBundledSkills: true`. — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Body lifecycle: the rendered SKILL.md enters the conversation as a single message and stays across later turns — "every line is a recurring token cost." Identical re-invocation adds an "already loaded" note rather than a second copy. After auto-compaction, the most recent invocation of each skill is re-attached keeping the first 5,000 tokens of each, with a combined 25,000-token budget across skills (most recently invoked first) — so put the most important instructions near the top. — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Subagents with preloaded skills (`skills` field in subagent definition) receive the full skill content at startup (not progressive). — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- `context: fork` (+ `agent: Explore` etc.) runs a skill in a subagent that doesn't see history; only the result returns to the main context. `agent: Explore` starts without CLAUDE.md files. Use only for skills with explicit tasks. — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Dynamic context injection `` !`command` `` runs before the model sees the skill and its output replaces the placeholder; oversized output arrives as file path + short preview; a non-zero exit aborts the invocation (use `|| true`). — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Measurement tools for skills: `/skill-doctor` (v2.1.252+) reports each skill's context cost and usage and flags never-invoked skills; skill-creator benchmark mode aggregates pass rate, time and tokens with vs without skill into `benchmark.json`; `claude plugin eval` with a `tool_used: Skill` grader measures trigger rate; `claude plugin validate` finds broken frontmatter. — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- Gemini CLI follows the Agent Skills open standard: name/description loaded upfront, `activate_skill` tool loads the body when a task matches the description; locations `.gemini/skills/` and `~/.gemini/skills/`; contrasted with always-loaded GEMINI.md. — [Gemini CLI Agent Skills docs (search snippet)](https://geminicli.com/docs/cli/skills/); [DEV Community write-up](https://dev.to/playfulprogramming/gemini-cli-skills-teaching-your-terminal-agent-how-to-think-2541)
- The open format spec and eval workflow live at agentskills.io (linked from Claude Code docs). — [Claude Code skills docs](https://code.claude.com/docs/en/skills) → [agentskills.io evaluating skills](https://agentskills.io/skill-creation/evaluating-skills)

### Inferences
- Toolkit lint rules that follow directly from the docs: (a) name regex `^[a-z0-9-]{1,64}$`, no `claude`/`anthropic`; (b) description ≤1,024 chars hard, with a soft target well under that (e.g., ≤300 chars) because the always-loaded listing is shared by all skills under a ~1%-of-context budget (~2,000 tokens ≈ ~8,000 chars on a 200K window; this conversion is an estimate); (c) first sentence = primary trigger; (d) body ≤500 lines; (e) no nested reference chains; (f) TOC required on references >100 lines.
- "Description bytes × number of skills" is the single biggest always-on cost a skill toolkit controls; a large toolkit should ship rarely used/user-only skills with `disable-model-invocation: true` and recommend `skillOverrides: name-only` for low-priority ones.
- Because the body persists for the rest of the session and only the first 5,000 tokens survive compaction, front-load imperative rules and push rationale/examples into reference files.
- Since Gemini CLI and Claude Code share the SKILL.md standard, the same skill directory can serve both; keep tool-specific frontmatter (e.g., `context: fork`, `allowed-tools`) optional so other runtimes ignore it.

- Could not fetch the Oct 2025 "Equipping agents for the real world with Agent Skills" post itself in this session; its claims are covered here via the best-practices and Claude Code docs. No official per-skill token figure for metadata was found.

## 2. Tool/context bloat: MCP tool-definition overhead, tool search / deferred loading, code execution with MCP, programmatic tool calling, tool result sizes

### Takeaway
Tool definitions are often the largest fixed context cost (a 5-server setup ≈55K tokens; Anthropic saw 134K). Deferred loading via tool search cuts this ~85% and raised MCP-eval accuracy; programmatic tool calling cut tokens 37% on complex tasks; "code execution with MCP" cut a workflow from 150K to 2K tokens (98.7%). Claude Code now defers MCP tools by default, caps descriptions/instructions, and caps/persists large outputs. Tool authors should add `response_format` concise/detailed, pagination, filtering and truncation with steering messages.

### Cited Findings
- Measured MCP definition overhead: GitHub 35 tools ≈26K tokens; Slack 11 tools ≈21K; Sentry 5 ≈3K; Grafana 5 ≈3K; Splunk 2 ≈2K; five servers = 58 tools ≈55K tokens; Jira alone ≈17K; setups with more servers pass 100K+; Anthropic saw tool definitions consume 134K tokens before optimization. — [Introducing advanced tool use (Anthropic, Nov 24 2025)](https://www.anthropic.com/engineering/advanced-tool-use)
- Tool Search Tool: upfront cost ≈500 tokens + 3–5 discovered tools ≈3K → ≈8.7K total vs ≈77K traditional; 85% token reduction; 191,300 vs 122,800 tokens of context preserved; MCP-eval accuracy Opus 4 49%→74%, Opus 4.5 79.5%→88.1%. Use `defer_loading: true`; keep the 3–5 most-used tools non-deferred. Recommended when definitions >10K tokens, 10+ tools, or multiple MCP servers. — [Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)
- Programmatic Tool Calling (Claude writes code that calls tools; intermediate results stay out of context): average tokens 43,588→27,297 (37% reduction) on complex research tasks; budget example ~200KB raw data → ~1KB result; 20+ tool calls in one code block eliminating 19+ inference passes; accuracy gains 25.6%→28.5% (internal retrieval), 46.5%→51.2% (GIA). Best for large datasets, 3+ dependent calls, or results needing filtering. — [Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)
- Tool Use Examples (1–5 examples per tool): complex parameter accuracy 72%→90% (internal). Note: examples add tokens to definitions, so pair with deferred loading. — [Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)
- Code execution with MCP (Nov 4 2025): present MCP servers as a filesystem of per-tool code files the agent lists/reads on demand; `search_tools` with detail levels (names only / +descriptions / full schemas); filter data in the sandbox (10,000-row sheet → agent sees 5 rows); loops in code; PII tokenization; state persisted to files; save working code as reusable functions + SKILL.md. Example: 150,000 → 2,000 tokens (98.7%). Caveat: requires secure sandboxing, resource limits and monitoring. — [Code execution with MCP (Anthropic)](https://www.anthropic.com/engineering/code-execution-with-mcp)
- Claude Code today: MCP tool definitions are deferred by default — only tool names and server instructions load at session start. `ENABLE_TOOL_SEARCH` = unset/`true` (defer), `auto` (load upfront while definitions <10% of context window; defer at ≥10%), `auto:N` (custom %), `false`. Per-server `alwaysLoad: true|false` to exempt/force deferral. — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp)
- Claude Code description caps: server instructions and upfront tool descriptions 4,096 chars; descriptions of tools loaded through tool search 16,384 chars (tunable via `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`); before v2.1.296 the upfront limit was 2,048 chars. Tool search reads only the part within the shorter limit when matching, so put searchable keywords and critical details first. Server instructions act like a skill description to tell Claude when to search for your tools. — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp)
- Claude Code MCP output limits: warning when a tool output exceeds 10,000 tokens; default cap 25,000 tokens (`MAX_MCP_OUTPUT_TOKENS`); successful text results >50,000 chars are persisted to a file and replaced with a file reference unless the tool sets `_meta["anthropic/maxResultSizeChars"]` (hard ceiling 500,000 chars). — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp)
- "Prefer CLI tools when available": `gh`, `aws`, `gcloud`, `sentry-cli` "are still more context-efficient than MCP servers because they don't add any per-tool listing"; disable unused servers via `/mcp`. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- Tool-response design: offer a `response_format` enum (CONCISE/DETAILED) — example 206 vs 72 tokens, Slack example ≈1/3 tokens; add pagination, range selection, filtering or truncation with sensible defaults; when truncating, steer the agent toward many small targeted searches; return semantic names instead of UUIDs (reduced hallucination); namespace tools by service/resource; consolidate multi-step workflows (e.g., `search_logs` returning only relevant lines). Claude Code limits tool responses to 25,000 tokens by default. — [Writing effective tools for agents (Anthropic, Sep 11 2025)](https://www.anthropic.com/engineering/writing-tools-for-agents)
- "Keep tool sets small with minimal overlap… If a human engineer can't clearly choose a tool, the agent likely can't either." — [Effective context engineering for AI agents (Sep 29 2025)](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Hooks can preprocess output before the model sees it: a PreToolUse hook rewriting `npm test|pytest|go test` to `… | grep -A 5 -E '(FAIL|ERROR|error:)' | head -100`; grep a 10,000-line log for `ERROR` instead of reading it — "from tens of thousands of tokens to hundreds." — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- Code intelligence (LSP) plugins: one "go to definition" call replaces grep + reading multiple candidate files. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)

### Inferences
- For a plugin toolkit shipping MCP servers: write rich, keyword-first server `instructions` (≤4,096 chars), keep any `alwaysLoad` tools to the 3–5 hottest, mark large-output tools with `anthropic/maxResultSizeChars` only where truly needed, and default every list/search tool to paginated, concise output.
- Where a CLI exists, ship a skill that wraps the CLI (zero listing cost beyond the skill description) rather than an MCP server; reserve MCP for auth-heavy/remote services.
- Ship reusable PreToolUse/PostToolUse "output filter" hooks (test runners, linters, log readers) as part of the toolkit — cheapest, model-agnostic savings in Claude Code.
- Code-execution/PTC patterns are portable to Codex/Gemini only if the toolkit provides scripts the agent can run in its own shell; package "tool as script + SKILL.md" rather than relying on API-only features.

### Gaps
- No independent (non-Anthropic) replication of the 85% / 98.7% figures found in this session.
- Equivalent deferred-tool mechanisms in Codex CLI / Gemini CLI / Cursor not verified (official docs blocked).

## 3. Context management: prompt caching, context editing / tool-result clearing, compaction, memory, subagents as isolation, context-engineering guidance

### Takeaway
Order prompts static→dynamic (tools → system → messages) and never mutate early blocks; cache reads cost 0.1x (0.05x/0.025x on newest models) vs writes 1.25x (5 min) / 2x (1 h). Context editing (clear old tool results) gave 29% task improvement and 84% token reduction in a 100-turn eval (39% with memory). Subagents isolate verbose work and return ~1–2K-token summaries, but multi-agent systems use ~15x chat tokens (agent teams ~7x a standard Claude Code session), so they are a quality/latency play, not a token saver overall.

### Cited Findings
- Prompt caching prefix order is `tools` → `system` → `messages`; a change at one level invalidates that level and all later ones. Changing tool definitions invalidates everything; `tool_choice` or adding/removing images invalidate system+messages; thinking/effort changes always invalidate message blocks. — [Prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Pricing multipliers: 5-min write 1.25x, 1-hour write 2x, read 0.1x base input (0.05x on Opus 5.5 / Sonnet 5.5; 0.025x on Fable 5.1 / Mythos 5.1). 5-min TTL refreshes free on each hit. Up to 4 breakpoints; lookback window 20 positions per breakpoint. Minimum cacheable length 512 tokens on current 5.x models, 1,024 on Sonnet 4.5/4.6, 4,096 on Opus 4.5/4.6 and Haiku 4.5 (silent no-cache below minimum; check `cache_creation_input_tokens`/`cache_read_input_tokens`). — [Prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Best practices: breakpoint on the last block identical across requests; keep timestamps/per-request context after it; add a second breakpoint if conversation grows >20 blocks past last write; keep JSON key order stable in `tool_use` blocks. — [Prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Cost math example (derived from the multipliers above): a 20K-token static prefix reused across 10 requests within TTL costs 1.25×20K + 9×0.1×20K = 43K token-equivalents vs 200K uncached (~78% saving); break-even for a 5-min write is the 2nd request (1.25 + 0.1 < 2). — derived from [Prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Claude Code `/usage` shows a `Prompt cache (main)` line (v2.1.251+): % of input from cache, misses with likely cause (e.g., "tool definitions changed", v2.1.260+), expected rebuilds after compaction/tool-result clearing, warm/cold with TTL. Cache misses after idle > TTL reprocess the full context. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- Context editing (Sep 29 2025): auto-clears stale tool calls/results near limits; memory tool = client-side file directory with CRUD via tool calls, persisting across conversations. Internal agentic-search eval: context editing +29%, context editing + memory +39%; in a 100-turn web-search eval, 84% token reduction and completion of workflows that otherwise failed from context exhaustion. — [Managing context on the Claude Developer Platform](https://claude.com/blog/context-management)
- API specifics: beta header `context-management-2025-06-27`; `clear_tool_uses_20250919` defaults trigger 100,000 input tokens, keep 3 tool uses, `clear_at_least` (use it so savings justify the cache re-write), `exclude_tools`, `clear_tool_inputs: false`; `clear_thinking_20251015` (must be listed first); `count_tokens` returns post-clearing `input_tokens` and `context_management.original_input_tokens`. Server-side compaction `compact_20260112` is the recommended primary strategy for long conversations; client SDK `compaction_control` (threshold 100,000) is deprecated. — [Context editing docs](https://platform.claude.com/docs/en/build-with-claude/context-editing)
- Context engineering principles: context rot (recall degrades as tokens grow); attention budget (n² pairwise relations); goal = "the smallest possible set of high-signal tokens"; right-altitude system prompts (minimal ≠ short); few canonical examples over long edge-case rule lists; just-in-time retrieval via lightweight identifiers (paths, queries, links); compaction (tune for recall then precision; Claude Code keeps the summary plus five most recently accessed files); tool-result clearing as lightest compaction; structured note-taking (NOTES.md, to-do lists); subagents return condensed ~1,000–2,000-token summaries. — [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Multi-agent cost: agents ≈4x chat tokens; multi-agent ≈15x chat tokens; token usage alone explains 80% of BrowseComp variance; Opus-4-lead + Sonnet-4-subagents beat single Opus 4 by 90.2% on internal research eval; poor fit for tasks requiring shared context or many inter-agent dependencies — "most coding tasks." (Jun 13 2025; models now superseded.) — [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- Claude Code: agent teams use ≈7x more tokens than standard sessions when teammates run in plan mode; each teammate loads CLAUDE.md, MCP servers and skills automatically; keep spawn prompts focused, use Sonnet for teammates, shut them down when done. Delegate tests/doc fetching/log processing to subagents so verbose output stays out of the main context; pick `model: haiku` for simple subagents. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- Claude Code compaction: `/compact <focus>` and a "# Compact instructions" section in CLAUDE.md steer what's preserved; `/compact` itself is a large request; `/clear` is free. Hidden background costs: session recap, idle compaction, prompt suggestions (mostly cache reads), scheduled `/loop` tasks, goal check-ins (capped at 3 idle check-ins), cross-session messages. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)

### Inferences
- Toolkit rule: never inject volatile data (dates, git status, random IDs) into always-loaded files or early system blocks; put dynamic context in the latest user turn or via `!command` in skill bodies invoked later. Avoid hooks that mutate tool lists mid-session (invalidates the whole cache).
- Subagent guidance for toolkit authors: define subagents with explicit return-format contracts ("return ≤N bullet summary + file paths"), smaller models, and minimal tool allowlists; use them for read-heavy exploration, not tightly coupled coding.
- A file-based memory convention (NOTES.md / progress file) is portable across Claude Code, Codex, Gemini CLI and Cursor because it relies only on file read/write.

### Gaps
- No public per-model figures for compaction quality loss; server-side `compact_20260112` trigger defaults not captured (page truncated).
- No measured comparison of 5-min vs 1-hour TTL economics for interactive coding sessions found.

## 4. Repo maps and code-context retrieval (brief)

### Takeaway
Anthropic's guidance favors just-in-time retrieval (paths, grep, LSP) over preloading repo overviews, and a 2026 ICLR paper found repository-overview context files don't help and raise cost >20%; LSP-based navigation is the documented token saver in Claude Code.

### Cited Findings
- Just-in-time strategy: keep lightweight identifiers and load data at runtime with tools; hybrid approaches preload some data for speed. — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Code intelligence plugins: a single "go to definition" call replaces grep + reading multiple candidate files; LSP also reports type errors after edits. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- A "codebase-overview" skill can give architecture/directories/conventions on demand instead of exploration, and only loads when invoked. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- Gloaguen et al., "Evaluating AGENTS.md" (arXiv 2602.11988, ICLR 2026): across agents (Claude Sonnet 4.5, GPT-5.2, GPT-5.1 mini, Qwen3-30b-coder), context files gave no improvement in task success while increasing inference cost >20%; LLM-generated files added 3.92 steps (+23% cost) on their benchmark and 2.45 steps (+20%) on SWE-bench; repository overviews specifically not helpful; human-written minimal files did better. Caveat: Python-only, issue-style tasks. — [arxiviq summary](https://arxiviq.substack.com/p/evaluating-agentsmd-are-repository); [ICLR 2026 listing](https://iclr.cc/virtual/2026/10021142); [opentrain.ai paper page](https://www.opentrain.ai/papers/evaluating-agents-md-are-repository-level-context-files-helpful-for-coding-agent--arxiv-2602.11988/)

### Inferences
- A toolkit should ship repo-map generation as an on-demand skill/script (output written to a file and grepped), not as always-loaded AGENTS.md/CLAUDE.md content.

### Gaps
- Deep repo-map benchmarking (Aider-style maps, embeddings vs grep) deliberately left to the other researcher.

## 5. Output-side efficiency: concise output, structured output, effort/thinking budgets

### Takeaway
Output and thinking tokens are billed as output (the most expensive tokens); the main levers are effort level (`/effort`, `output_config.effort`), `MAX_THINKING_TOKENS` on fixed-budget models, concise tool-response formats, and returning summaries from subagents.

### Cited Findings
- Thinking tokens are billed as output tokens; the default budget can be tens of thousands of tokens per request. Lower effort via `/effort` or `/model`, or disable thinking in `/config` (not possible on Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable — always-thinking). On fixed-budget models set `MAX_THINKING_TOKENS` (e.g., 8000); adaptive-reasoning models ignore nonzero budgets, use effort instead. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- `/usage` recommendations include rows like "40% Switch from max to high effort · /effort high"; `f` applies them (v2.1.305+). — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- Changing `output_config.effort` or thinking parameters invalidates cached message blocks — set effort once per session/agent, don't toggle per turn. — [Prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Concise response format cut a tool response from 206 to 72 tokens. — [Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)
- Template pattern: give strict output templates where format matters (also reduces rework). — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Telemetry carries an `effort` attribute on token/cost metrics, enabling measurement of effort-level impact. — [Claude Code monitoring docs](https://code.claude.com/docs/en/monitoring-usage)

### Inferences
- Subagent/skill definitions in the toolkit should pin `model` and (where supported) effort per role: low effort + small model for search/format/summarize roles; high only for planning/review.
- Instruct subagents to return terse structured summaries (paths + findings) — this both cuts output tokens and the main-context input they create.

### Gaps
- No quantified study found on "concise output style" instructions vs token savings for coding agents in 2025–2026.

## 6. Measurement: token counting, /context, telemetry, CI budgets

### Takeaway
Claude Code exposes per-skill/plugin/MCP/subagent token attribution via `/usage`, `/context`, `/doctor`, `/skill-doctor`, and OpenTelemetry (`claude_code.token.usage` with `skill.name`, `plugin.name`, `mcp_server.name`, `agent.name`); the API's `count_tokens` endpoint can be used in CI to enforce budgets on always-loaded text.

### Cited Findings
- `/context` shows what's consuming space, including `(deferred)` / `(loaded on-demand)` tool labels and a post-budget Skills row. — [Claude Code costs docs](https://code.claude.com/docs/en/costs); [Claude Code MCP docs](https://code.claude.com/docs/en/mcp); [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- `/usage` plan breakdown attributes recent usage to skills, subagents, plugins and individual MCP servers (as %), and recommends changes for behaviors ≥10% of usage, e.g., "25% Trim ~/code/api/CLAUDE.md · 49k tokens per request". — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- `/skill-doctor` reports per-skill context cost and usage, flags never-invoked skills; `/doctor` estimates skill listing cost and biggest contributors. — [Claude Code skills docs](https://code.claude.com/docs/en/skills)
- OpenTelemetry: enable with `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_METRICS_EXPORTER=otlp`, `OTEL_LOGS_EXPORTER=otlp`. Metrics `claude_code.token.usage` (`type` = input/output/cacheRead/cacheCreation) and `claude_code.cost.usage`; events `claude_code.api_request` (tokens incl. `cache_creation_5m_tokens`/`_1h_tokens`, cost) and `claude_code.tool_result` (`tool_result_size_bytes`, `tool_input_size_bytes`). ### Inferences
- A CI "context budget" job for the toolkit can: (1) sum all skill `description` (+`when_to_use`) chars and fail above a threshold (e.g., keep total under the ~1% listing budget for the smallest supported context window); (2) count tokens of always-loaded files (CLAUDE.md/AGENTS.md/GEMINI.md/always-apply Cursor rules) via `count_tokens` or a tokenizer approximation, failing above N tokens; (3) enforce per-file byte limits matching Codex's 32 KiB cap; (4) fail if SKILL.md >500 lines or reference nesting >1; (5) check MCP server instructions ≤4,096 chars and upfront tool descriptions ≤4,096 chars; (6) run `claude plugin validate`.
- Runtime regression tracking: export OTel to a dashboard grouped by `skill.name`/`plugin.name`/`mcp_server.name` to spot expensive components; track cache-hit ratio from `cacheRead` vs `input`.

## 7. Equivalent mechanisms in other agents (Codex AGENTS.md, Gemini CLI GEMINI.md/extensions, Cursor rules)

### Takeaway
All major agents have an always-loaded instruction file (AGENTS.md / GEMINI.md / CLAUDE.md / always-apply rules) plus a lazier mechanism (Codex nested files with a 32 KiB total cap; Gemini skills and `@` imports; Cursor glob/description-scoped rules). A cross-LLM toolkit should keep the shared always-loaded file tiny and push everything else into skills or scoped rules.

### Cited Findings
- Codex: per directory looks for `AGENTS.override.md`, then `AGENTS.md`, then fallback names (`project_doc_fallback_filenames`); at most one file per directory; skips empty files; stops adding once combined size reaches `project_doc_max_bytes` (32 KiB default); fix by raising it (example 65536) or splitting into nested directories. — [OpenAI Codex AGENTS.md guide (search snippet)](https://developers.openai.com/codex/guides/agents-md)
- Codex truncation details (third-party): default 32,768 bytes; a file that doesn't fit is cut at a byte offset and later files are never read; budget is bytes not characters (CJK = 3 bytes/char); nested files can crowd out parent files. — [wikidocs (Korean)](https://wikidocs.net/370962); [thepromptshelf guide](https://thepromptshelf.dev/blog/agents-md-codex-setup-guide-2026/)
- Gemini CLI: concatenates all found context files (global `~/.gemini/GEMINI.md`, project/ancestor files, subdirectory files) and sends them with every prompt; `@file.md` imports; `/memory show` and `/memory refresh`; `context.fileName` can list multiple names (e.g., AGENTS.md alongside GEMINI.md); respects .gitignore/.geminiignore; `/stats` shows token usage. — [Gemini CLI GEMINI.md docs (search snippet)](https://geminicli.com/docs/cli/gemini-md.md); [google-gemini.github.io gemini-md](https://google-gemini.github.io/gemini-cli/docs/cli/gemini-md.html); [Addy Osmani tips](https://addyosmani.com/blog/gemini-cli/)
- Gemini CLI skills load name/description upfront and body via `activate_skill` on demand (see §1). — [Gemini CLI skills docs (search snippet)](https://geminicli.com/docs/cli/skills/)
- Cursor: project rules are `.mdc` files in `.cursor/rules/` with frontmatter `description`, `globs`, `alwaysApply`; modes = Always, Auto-attached by glob, Agent-requested by description, Manual via `@rule`; `.cursorrules` legacy/deprecated for Agent mode. Cursor includes always-on rules alongside Team Rules, User Rules, AGENTS.md and CLAUDE.md in every Agent chat; CLAUDE.md is applied to every conversation regardless of alwaysApply. Nested AGENTS.md files combine with parents. Sources conflict on whether plain `.md` files in `.cursor/rules/` are ignored or treated as manual-only. — [mer.vin deep dive (Dec 2025)](https://mer.vin/2025/12/cursor-ide-rules-deep-dive/); [morphllm .mdc guide](https://morphllm.com/cursor-mdc-rules); [StackHawk](https://www.stackhawk.com/blog/cursor-rules/); [DEV Community](https://dev.to/olivia_craft/your-cursorrules-file-isnt-working-in-cursor-agent-mode-migration-guide-4l11)
- Claude Code: keep CLAUDE.md under 200 lines; move workflow-specific instructions into skills which load on demand. — [Claude Code costs docs](https://code.claude.com/docs/en/costs)
- Minimal human-written context files outperform generated/overview-heavy ones; context files raise cost >20% when bloated. — [Evaluating AGENTS.md (arxiviq summary)](https://arxiviq.substack.com/p/evaluating-agentsmd-are-repository); "less is more" practitioner view — [Upsun developer blog](https://developer.upsun.com/posts/ai/agents-md-less-is-more)

### Inferences
- Cross-agent layout recommendation: one short canonical `AGENTS.md` (well under 32 KiB, ideally <200 lines) symlinked/imported as CLAUDE.md and GEMINI.md (or Gemini `context.fileName: ["AGENTS.md"]`); procedural knowledge in `skills/*/SKILL.md` (works in Claude Code and Gemini CLI); Cursor gets generated `.cursor/rules/*.mdc` with `globs`/`description` (not `alwaysApply`) derived from skill descriptions.
- Because Cursor loads CLAUDE.md and AGENTS.md together, duplicating content across both doubles cost there — the toolkit should have one source and reference the other.
- Byte-based Codex budget means the toolkit's CI should measure bytes, not tokens or lines, for AGENTS.md chains.
